# generate-subtitle: Capabilities and use cases

English | [简体中文](../../skills-zh-CN/generate-subtitle/README.md) | [Back to repository home](../../README.md) | [Agent instructions](SKILL.md)

**The goal: almost never needing to correct subtitles manually.** Combine local transcription, conservative correction, and automatic formatting, then keep accumulating your frequently used product names, proper nouns, and records of recognition corrections to reduce the work of fixing text entry by entry and manually adjusting subtitle breaks each time.

Give the agent local video, audio, or existing subtitles to handle the work from transcription and correction through subtitle delivery. Suitable for recorded talking-head videos, tutorials, interviews, and podcasts: it can process a single file, join multiple videos into one set of compilation subtitles, or align multiple audio files recorded simultaneously on several devices and separate them into tracks (for group conversations with audio captured on separate devices). When needed, it can also save translated subtitles separately, extract chapter titles and key highlight captions, and generate a content review checklist before publishing.

## Typical usage

After installation, use the following prompts in an agent session, replacing the example paths with the paths to your own materials.

| Scenario | Example prompt |
| --- | --- |
| Talking-head / tutorial subtitles | “Use generate-subtitle to generate original-language subtitles for `/path/to/video.mp4`, correct obvious typos, standardize product names and terminology, preserve discourse particles, and list anything that needs my confirmation.” |
| Multi-video compilation | “Use generate-subtitle to process the videos in `/path/to/videos/`. First list their order for me to check, then join them end to end in that same order to generate one set of compilation subtitles.” |
| Multi-person interview / podcast | “Use generate-subtitle to process multiple audio files in `/path/to/audios/`, recorded simultaneously with one device per person. First check the alignment results and speaker mapping, then output combined subtitles and a separate subtitle file for each person.” |
| Foreign-language audio/video | “Use generate-subtitle to generate English original-language subtitles for `/path/to/interview.mp4`. After uncertain content has been confirmed, save a separate copy of Chinese subtitles.” |
| Translating existing subtitles | “Use generate-subtitle to translate `/path/to/video.srt` into English. Preserve the original subtitles and save the translation separately as `video.en.srt`, keeping the numbering and timeline unchanged.” |
| Chapters, highlight captions, and review before publishing | “Use generate-subtitle to process `/path/to/tutorial.mp4` and generate subtitles. If anything is uncertain, ask me to confirm it first, then check for sensitive or offensive content and extract chapter headings and key highlight captions.” |

## Main capabilities

- **Local transcription, with an engine selected for the language and materials.** For Chinese, **FireRedASR2S** is preferred by default, falling back to **FunASR** if it is not installed; FunASR is used when Chinese audio mixed into a single track requires voiceprint-based speaker diarization. **Whisper** is used for non-Chinese content or when language detection is uncertain. Original-language subtitles are generated by default; translation is performed only when explicitly requested. Models may need to be downloaded on first use; transcription results are cached locally and can be reused when the input and relevant configuration remain unchanged.
- **Join multiple videos and align recordings from multiple devices.** Multiple videos are sorted by creation time and joined into a single timeline; multiple audio files recorded simultaneously on several devices are aligned by sound to determine their starting offsets, and any detected substantial clock drift is corrected. Before processing, use `--dry-run` to check the order, offsets, and track mappings; the results are written to the manifest. Compilation subtitles correspond to a finished video assembled by joining the clips end to end in the same order. If portions are cut out, the timeline must be matched again.
- **Separate speakers by channel, device, or voiceprint.** Tracks are separated automatically when each person has a microphone and occupies a separate left or right channel; when each person uses a separate device, separation follows the recording tracks. Crosstalk suppression where applicable, duplicate cleanup, and cross-track checks by the agent help reduce repeated instances of the same utterance; in combined subtitles, two people speaking simultaneously can be combined into two lines, one above the other. Voiceprint-based diarization of audio mixed into a single track is currently limited to the Chinese FunASR path; FireRedASR2S and Whisper do not provide voiceprint-based diarization. When multiple people share a device track, device-based track separation alone cannot distinguish them either.
- **Conservative correction that preserves spoken style.** By default, confidently identified errors involving identical or similar sounds are corrected, proper nouns are standardized using the glossary and context, and discourse particles are preserved; uncertain passages are listed in subtitles awaiting confirmation. Chinese content also receives handling for misrecognized consecutive repetitions, year notation, and spacing between Chinese and English; the `clean` level can be selected when filler removal is explicitly needed. Chinese-specific rules are not applied directly to other languages.
- **Automatic segmentation, formatting, and timeline cleanup.** Subtitles are split according to timestamps and pauses, preserving English words, product names, and terminology, and cleaning up entries that overlap, are too short, or linger too long. The default target line width is 16 Chinese characters, with ordinary English letters and digits counted as half-width; lines may moderately exceed this width to keep terms intact, so it is not an absolute hard limit of 16 characters.
- **Translate, extract chapters and highlight captions, and review content for publishing as needed.** Translation can use existing subtitles directly, preserving the original text, numbering, timeline, and speaker markers, and saving a separate target-language version. Chapter headings and key highlight prompts are combined in a single highlight subtitle file. Content review flags high / medium / low risks in four categories—sensitive information, personal attacks, distressing content, and offensiveness—with the original text, time locations, and suggested actions for a person to decide what to delete or revise.

## Build a glossary of recognition errors

**When you encounter a recognition error, correct the current subtitles and remind the agent to save the “incorrect form → correct form” mapping in the glossary as reusable material for future corrections.** Product names, industry terminology, and recurring homophone recognition errors are especially useful to collect; include the applicable context for ambiguous terms to avoid incorrect changes in other content.

You can say directly: “The ‘卡索’ here should be ‘Cursor’. Please correct the subtitles and save this correction in the local project's glossary; load this glossary when processing similar content in the future as well.” Load a project glossary with `--glossary` to use it alongside the skill's bundled `glossary.txt`.

After a few uses on the same topic, continuing to add confirmed common errors to the glossary can gradually reduce repeated text corrections and bring you closer to **almost never needing to correct subtitles manually**. The improvement comes from reusing these records during later corrections; actual results still depend on recording quality, content, and glossary coverage. Continue listening to the original audio to confirm uncertain subtitles as prompted.

## Files you will receive

The following uses SRT output as an example; separate speaker tracks, translations, highlight captions, and review files are generated according to the materials and selected features.

| File | Purpose |
| --- | --- |
| `<名字>.srt` / `<名字>.raw.srt` | Corrected combined subtitles and the original ASR text for comparison, making it easier to import into an editor and review changes |
| `<名字>.spkN.srt` / `<名字>.spkN.raw.srt` | Subtitles for each speaker and the original text for each track for comparison, making it easier to proofread or use them separately |
| `<名字>.uncertain.srt` | Uncertain text and candidate corrections, with timecodes for jumping to the original audio to confirm |
| `<名字>.dedupe.md` / `<名字>.manifest.json` | A comparison of deduplication changes, plus records of source file order, time offsets, track mappings, and more |
| `<名字>.en.srt`, etc. | Translated subtitles saved separately; the language code changes with the target language |
| `<名字>.highlights.srt` | Chapter headings and key highlight captions that can be imported into an editor as overlays |
| `<名字>.review.srt` / `<名字>.review.md` | Timecoded subtitles for locating content flagged for review, plus a list of risk explanations and suggested actions |

## Using subtitles with video editing software

The generated SRT files contain subtitle text and timecodes. You can drag them into editing software that supports SRT import, or load them through its “Import subtitles” option, then continue editing the text and styling. The exact import method, support for multiple subtitle tracks, and styling options depend on the software you use.

1. **Align the source media timeline first.** Subtitles for a single file correspond to the time positions in the original media; join multiple videos end to end in the order recorded in the manifest; align recordings from multiple devices using the recorded offsets. Keep the same starting point when importing subtitles. Recordings from multiple devices also need to be synchronized with the video; you can check by listening at the beginning, middle, and end.
2. **Import the combined subtitles, or import each speaker's subtitles separately.** Use `<名字>.srt` to apply a consistent dialogue style throughout the video. To distinguish people, drag `<名字>.spk1.srt`, `<名字>.spk2.srt`, and so on separately into a project that supports multiple subtitle tracks, and set a different color, position, or style for each person. These files share a timeline, so retain their original timecodes. Usually, display either the combined subtitles or the per-speaker subtitles to avoid overlaying the same utterance twice.
3. **Import chapter and highlight captions, then continue styling them.** Import `<名字>.highlights.srt` as an additional subtitle layer. It contains both chapter headings marked with `【N】` and key highlight captions. You can select these entries separately and adjust the font, font size, color, outline, position, and display duration; if the software supports it, you can also add backgrounds or entrance and exit animations. Chapter titles can be enlarged and centered, while key highlight captions can be placed above the dialogue subtitles, with placement adjusted to the available space in the frame.
4. **Use auxiliary subtitles to locate passages that need checking.** Temporarily import `.uncertain.srt`, jump to each entry to listen to the original audio, and apply the confirmed text to the subtitles for the final video. Use `.review.srt` together with `.review.md` to locate content that needs deletion or revision. Once finished, hide or remove these auxiliary subtitles, leaving only the subtitle layers intended for viewers before exporting.

**The actual workflow is: transcription and correction → human confirmation by listening to the original audio when anything is uncertain → translation, content review, and highlight captions as needed.** Automatic formatting reduces manual adjustment, but uncertain text, highlight captions, and review results still need to be checked. Highlight captions are delivered as subtitle text and timecodes; their visual styling is set in the editor.

ASR runs locally; correction, translation, highlight captions, and review are handled by the current agent session. When a cloud model is used, the relevant text enters the model's context.
