# 视频字幕生成 Skill

## 语言规则与路由

默认输出音频原语言字幕，**与 Skill 文档使用中文还是英文无关**。纠错保留原语言和混合语言，不自动翻译。保留一个 Skill 入口，内部中文 / Whisper 两条转写路径共用分轨、纠错、翻译与时间轴校验。

- `--language` 是音频语言提示，默认 `auto`，不代表翻译。自动识别为中文时沿用原引擎规则；非中文或语言不确定时走 Whisper。
- `--translate-to` 仅在用户明确要求翻译时设置；先完成原语言纠错，再 handoff 翻译，另存 `<原名>.en.srt` 等文件。已有字幕可直接作为输入，不必重新转写。
- `--whisper-model` 选择多语言模型（默认 `small`），运行时检查实际语言支持，拒绝英语单语模型。
- 中文年份、去重、语气词清理、中英文空格等专项规则仅适用于明确的中文内容；不能套用到其他语言。纠错、花字和审查引用均保留原语言。
- FunASR 声纹分离仅按现有中文管线能力使用；不能宣称支持所有语言。声道 / 设备分轨继续适用于不同语言。

**处理非中文、自动语言检测、混合语言或翻译任务前，读 [多语言转写与翻译](references/multilingual.md)**：包含依赖、检测局限、MPS 回退、翻译续跑和结构校验。

## 发布项目目录

同一内容的文章、文案、封面、视频共用 `Publish/<项目>/`；先复用确属同一内容的已有项目，新内容才创建本地 `YYYYMMDD-HHmm-主题` 目录。字幕及可复用转写中间物放进该项目的 `subtitles/`。保留已有文件名和用户显式输出路径；相似主题不足以认定为同一项目。本约定自包含，无需读取其他仓库的发布规范。


按顺序四步，**不要跳步**：

1. `generate_subtitle.py` —— 视频 → **ASR 原始字幕** + **纠错后的正片字幕** + **待确认字幕**
2. **人工确认待确认字幕**（`.uncertain.srt`，拖进剪辑器逐个跳转听原声），把机器没把握的地方改对
3. `make_review.py` —— 正片字幕 → 敏感/冒犯内容审查字幕 + 复核清单
4. `make_highlights.py` —— 正片字幕 → 关键重点提示字幕（花字，含章节分段提示）

**翻译为可选步骤**：用户要求时，在第 2 步后通过 `--translate-to` 或 `translate_subtitle.py` 另存译文。原字幕、编号、时间轴和说话人标记保留；无存疑时直接继续。

**第 2 步是硬性前置**：翻译、审查和花字都是基于字幕文字做语义判断，文字还错着就分析不准。
第 1 步带 `--translate-to`/`--with-review`/`--with-highlights` 时，若产出了待确认字幕会**主动停下**，让你先确认。

**每一步都可能中途停下来把 LLM 任务交给你做**（exit 10 + 一份任务清单），
做完重跑同一条命令续跑——见下方「先看这个：脚本会中途停下来找你干活」。

## 触发条件

- 给一个视频生成字幕
- 给一个目录里的多个视频生成**一个**合集字幕（按视频创建时间接续）
- 给多个**同时录制**的音频文件（对谈时每人面前一台录音设备 / 手机）生成字幕：自动对齐起始时刻、按设备和声道分出说话人，每人一份 + 总字幕一份
- 提取口播文字稿、去掉「呃嗯啊那个就是」这类水词
- 为教程/演示视频挑花字：关键信息提示 + 新章节开始提示
- 发布前检查视频里有没有敏感信息、人身攻击、让人不适或冒犯性的话
- 纠正字幕里的专有名词（`coso`→`Cursor`、`web coding`→`vibe coding` 这类）

## 依赖要求

- 中文路径需要 `funasr`、`torch`、`torchaudio`；自动语言检测 / Whisper 路径需要 `openai-whisper`，多语言分词和字宽需要 `regex`、`wcwidth`。下列命令使用 pipx 环境的解释器 `$HOME/.local/pipx/venvs/funasr/bin/python`；执行前确认该解释器和依赖可用。已装好时直接复用，其他环境则将命令中的解释器替换为实际路径。
- **可选第二引擎 FireRedASR2S**（`--engine firered`）跑在另一个 venv：`$HOME/.local/venvs/fireredasr2s/bin/python`，
  权重在 `$HOME/.cache/fireredasr2s/pretrained_models`（约 5.6GB）。没装时脚本会打印完整安装命令；
  两个 venv 不能合并——FireRedASR2S 的 `transformers`/`peft`/`torch` 版本会把 funasr 那个环境掀翻，
  所以主脚本仍用 funasr 的解释器跑，FireRedASR2S 以常驻子进程的形式被拉起（`firered_asr.py`）
- 本地安装 `ffmpeg` 和 `ffprobe`
- **LLM 部分只支持 handoff**：脚本生成任务后退出，由当前会话读取任务文件、完成纠错／翻译／花字／内容审查，再重跑续接。无需选择后端，也不检测或调用任何外部模型命令行程序。在普通终端执行同样会生成待办任务，不会自行完成模型分析。
- 首次运行会自动下载所选 ASR 模型，体积依引擎和模型而异
- `make_highlights.py` 和 `make_review.py` 不碰 ASR，用系统 `python3` 跑即可

## 使用方法

> 先定位已安装 skill 的目录，将下面的 `SKILL_DIR` 设为该目录。以下示例适用于用户级安装；直接使用共享仓库时可设为该仓库的 `skills-zh-CN/generate-subtitle/` 绝对路径。

```bash
SKILL_DIR="$HOME/.agents/skills/generate-subtitle"
```

### ⚠️ 先看这个：脚本会中途停下来找你干活（handoff）

在 agent 会话里跑时，脚本通过 handoff 交接模型任务，**不会**自己调 LLM，而是把每个 LLM 任务摊成一个任务目录后
**退出（exit code 10）**，等你做完再续跑。看到 `⏸ HANDOFF：N 个任务等你处理` 就照做：

1. 逐个读任务目录里的 `TASK.md`，按里面写的要求处理，结果写回**同一个目录**
   （JSON 类任务写 `out.json`；就地改文件的任务改完还要写一个 `DONE` 文件）
2. 任务之间互不依赖，**超过 2 个就并行分发给 subagent**（一条消息里发多个 Agent 调用），
   每个 subagent 只需要给它任务目录的绝对路径，让它自己读 `TASK.md`——prompt 不用重复任务规则
3. 全部写完后，跑脚本打印出来的**续跑命令**（它已经带好 `cd` 和 `-o`）
4. 再次看到 HANDOFF 就重复上面三步，直到脚本正常退出（exit 0）

> **`generate_subtitle.py` 续跑带 `-o` 指向原字幕文件或同一 `subtitles/` 目录**，
> 避免无法匹配旧项目时另建目录而失去缓存。脚本打印的续跑命令已经带上了。

任务目录在 `<输出目录>/.subtitle_tasks/`，做完不要删——重跑要靠它复用已完成的部分。

### 输出目录约定

用户没有指定产出目录（不带 `-o`）时，脚本先复用输入所属的 `Publish/` 项目或唯一同名主题项目；否则在 `Publish/` 下新建项目。Agent 应先检查同主题目录，名称不同但确认同一 case 时显式传 `-o <项目>/subtitles/`。字幕和中间物统一落在项目的 `subtitles/`：

- 目录名 `<YYYYMMDD-HHmm>-<名字>`，前缀用本地当前时间，例如 `20260813-2306`；重名自动追加 `-2`、`-3`
- `<名字>` 取输入目录名或主要视频文件名，去掉扩展名和前导日期时间（如 `2026-08-12 sample interview` → `sample interview`）
- `Publish/` 的位置：优先取 skill 所在仓库根目录下的（`$SKILL_DIR/../../../Publish`），独立安装且无法定位仓库时用当前工作目录下的
- `subtitles/` 里的内容：正片字幕、manifest、花字、复核清单、`.subtitle_cache/`（ASR 缓存）、`.subtitle_tasks/`（handoff 任务）
- `--dry-run` 只打印将要使用的项目目录路径，不实际创建
- 需要写到别处时（如用户明确要求放在源视频旁边），显式传 `-o`

**`-o` 可以给目录，也可以给字幕文件路径**：
- 给**目录**（或任何不以 `.srt`/`.vtt` 结尾的路径）→ 当项目目录，自动进入其 `subtitles/`；已经是 `subtitles/` 或其下级目录则直接复用
- 给 `xxx.srt` → 就写这个文件，中间产物落在它所在的目录

**中间产物落哪儿**（原则：会被二次利用的留在项目目录，纯过程物进系统临时目录）：

| 东西 | 落点 | 为什么 |
|---|---|---|
| 抽出来的 16k wav | 系统临时目录，用完即删 | 76 分钟访谈 ≈ 37MB，转写完立刻作废，没有回看价值 |
| `.subtitle_cache/` ASR 结果 | 项目内 `subtitles/` | **会被反复用**：改润色参数重跑、handoff 每轮续跑都读它，少了它每轮重转写整片。要挪走设 `SUBTITLE_CACHE_DIR` |
| `.subtitle_tasks/` handoff 任务 | 项目内 `subtitles/` | 题和答案都在里面，出问题要翻；重跑靠它复用。要挪走设 `SUBTITLE_HANDOFF_DIR` |

### 第 0 步：先确认这段素材里有几个人（**混音素材不能跳过**）

这一步不做，做到一半才发现认错人，代价是**整片重转**——`--speakers` 会进 ASR 缓存 key，
加或去这个开关等于之前的转写全部作废（76 分钟约 30~40 分钟）。而先问一句只要几十秒。

| 素材长什么样 | 怎么办 |
| --- | --- |
| 一人一支麦、各占左右声道（DJI Mic 之类） | **什么都不用做**，`--dual-channel auto` 自己判得出来，声道就是说话人，比声纹准 |
| 每人一台设备各录一个文件 | **什么都不用做**，`--layout auto` 会对齐并按设备分轨 |
| 混音的单轨、明确只有 1 个人 | **什么都不用做**，不开 `--speakers`（中文的 `auto` 优先 firered，其他语言用 Whisper） |
| **中文**混音的单轨、明确 N ≥ 2 个人 | `--speakers --speaker-count N`（引擎不用管，`auto` 自动切回 funasr 走 cam++） |
| **中文**混音的单轨、**不知道几个人** | 先跑 `--probe-speakers`（下面），别猜 |

用户没交代人数时**要问**，问不出来就探测——这是唯一能在浪费掉半小时之前拦住的地方。

```bash
# 声纹探测：抽开头 5 分钟跑一遍 cam++，只回答「有几个人」，不转写、不写任何文件
$HOME/.local/pipx/venvs/funasr/bin/python \
  "$SKILL_DIR/generate_subtitle.py" \
  "/path/to/audio.m4a" --probe-speakers --device mps
```

它会逐个文件打印各簇的说话时长占比，并直接给出建议参数：

```
[1/1] talk.m4a：听出 3 个人
        spk1    1.9 分   73%  主讲
        spk2    0.4 分   16%  主讲
        spk3    0.1 分    2%  疑似旁人
建议：
  talk.m4a: --speakers --speaker-count 2（引擎不用管，auto 会自动切回 funasr 走 cam++）
```

三个已知边界，别当成结论：

- **只看开头一段**（`--probe-seconds`，默认 300 秒），后面才出场的人数不到
- 左右声道判为两个人的文件会直接跳过并说明"不要开 `--speakers`"
- 多个音频文件走的是并行分轨，那条路上说话人 = 设备号，`--speakers` 不生效（见下面的已知限制），
  探测只用来告诉你"哪台设备前坐了不止一个人"

### 第 1 步：生成正片字幕

```bash
# 单个视频 → Publish/<YYYYMMDD-HHmm>-<视频名>/subtitles/<视频名>.srt
$HOME/.local/pipx/venvs/funasr/bin/python \
  "$SKILL_DIR/generate_subtitle.py" \
  "/path/to/video.mp4"

# 整个目录 → 按视频创建时间接成一条时间轴，只输出一个 <目录名>.srt
$HOME/.local/pipx/venvs/funasr/bin/python \
  "$SKILL_DIR/generate_subtitle.py" \
  "/path/to/videos/"

# 多个同时录制的音频文件（每人一台设备）→ 自动对齐到一条时间轴，每台设备各自分轨
$HOME/.local/pipx/venvs/funasr/bin/python \
  "$SKILL_DIR/generate_subtitle.py" "/path/to/audios/"

# 跑之前先确认视频顺序 / 音频对齐结果和分轨方案（不做转写，秒出）
$HOME/.local/pipx/venvs/funasr/bin/python \
  "$SKILL_DIR/generate_subtitle.py" "/path/to/videos/" --dry-run
```

**多文件时务必先跑一次 `--dry-run`**：接续布局核对顺序，并行布局核对对齐偏移和「哪轨是哪个人」，确认无误再正式转写。

#### ASR 引擎：先看音频语言

`--language auto` 逐文件、逐物理轨检测音频语言，中文沿用原规则：需声纹分离用 FunASR，否则优先 FireRed（缺失时退回 FunASR）。非中文或检测不确定用 Whisper。已知中文可用 `--language zh` 跳过检测；不能依据 Skill 文档语言设置该参数。

`--engine whisper` 可显式用于中文或混合语言；非中文即便指定中文引擎也会改走 Whisper并提示。单轨声纹分离仅支持当前中文 FunASR 管线，其他情况继续按声道/设备分轨。`--device auto` 优先 CUDA、MPS、CPU；Whisper 当前适配器在 MPS 选择下明确退回 CPU/FP32。详见[多语言说明](references/multilingual.md)。

两个引擎的实测差距（同一段 3 分钟双人中文对话，`--device mps`，关掉 LLM 纠错，只比 ASR 原文）：

- **FireRedASR2S 明显更准**：专有名词（`剪映`／FunASR 听成「检验」、`skill`／听成「sale」、
  `代账机构`／听成「代购机」、`找代账`／听成「找代驾」）几乎全对；FunASR 在这些位置全错
- **FunASR 会整句幻听**：「谁啊我认识吗？」被识别成「晚上吃吧」，FireRedASR2S 听对了
- **断句粒度**：FireRedASR2S 的 VAD+标点更细（同样 3 分钟切出 109 条字幕 vs FunASR 的 81 条，正文字数几乎相同），语气词「啊/嗯/诶」
  单独成条、笑声也留得住，更贴口语节奏；FunASR 倾向把几句黏成一条
- **FunASR 仍有零星胜场**：英文缩写大小写（`VP` vs firered 的 `bp`，两边都会串）、
  少数长句里 FireRedASR2S 会插一句幻听（「才越强大」）
- **耗时**：ASR 耗时取决于设备和引擎，模型任务耗时取决于当前会话的模型与字幕规模。handoff 等待不会触发脚本中的模型调用超时。
  `--device cpu` 时 FireRedASR2S 会再慢 4 倍（RTF≈2.2），这只是中文 FireRed 的本机实测，不代表 Whisper/MPS 兼容性

跑完得到：`<名字>.raw.srt`（ASR 原文，纠错的 diff 基线）、`<名字>.srt`（纠错后的总字幕）、
`<名字>.uncertain.srt`（待确认字幕）；凡是分出了说话人的素材（双声道 / 多设备并行 / `--speakers`）
还会多出**每人一份**纠错后的 `<名字>.spk1.srt` / `.spk2.srt`…，以及分轨原始对照 `<名字>.spkN.raw.srt`。

**分轨素材会走两轮 handoff**：先跨轨互校（把几个麦都收到的同一句话删到只剩一条），
再整份纠错。每轮都是「做完题重跑同一条命令」。

### 第 2 步：人工确认待确认字幕（**不能跳过**）

把 `<名字>.uncertain.srt` 拖进剪辑器，逐个跳转听原声核对，把机器没把握的地方改进 `<名字>.srt`。
每条的格式是 `【存疑】原文　→？候选改法1 ／ 候选改法2`。

改完后跑一次结构校验，确认没把时间轴改坏：

```bash
python3 "$SKILL_DIR/validate_subtitle.py" \
  "Publish/<项目目录>/subtitles/合集.raw.srt" \
  "Publish/<项目目录>/subtitles/合集.srt"
```

### 第 3 步：生成敏感/冒犯内容审查字幕

```bash
python3 "$SKILL_DIR/make_review.py" \
  "Publish/<项目目录>/subtitles/合集.srt" \
  --context "客户访谈录播"
```

### 第 4 步：生成关键重点提示字幕

```bash
python3 "$SKILL_DIR/make_highlights.py" \
  "Publish/<项目目录>/subtitles/合集.srt" \
  --context "Claude Code skill 教程"
```

第 1 步带上 `--with-review --with-highlights` 可以串起来，但**只要产出了待确认字幕就会停下**，
等你确认完再单独跑第 3、4 步——否则它们读的是还错着的文字。

### 常用参数

`generate_subtitle.py`：

| 参数 | 说明 | 默认值 |
|------|------|--------|
| `-o, --output` | 项目目录或字幕文件路径；不传时复用或新建 `Publish/` 项目，字幕落在 `subtitles/`（见「输出目录约定」） | 复用或新建项目 |
| `--engine` | 中文沿用 FunASR / FireRed 选择；非中文用 Whisper；也可显式选 `whisper` | `auto` |
| `--language` | 音频语言提示，不是翻译目标（如 `zh`、`en`、`ja`） | `auto` |
| `--translate-to` | 用户明确要求的翻译目标，原文纠错后另存；已有字幕可单独翻译 | 不翻译 |
| `--whisper-model` | 多语言模型名或 checkpoint 路径，加载后检查实际语言支持 | `small` |
| `--device` | `auto`=有 cuda 用 cuda、有 mps 用 mps、否则 cpu / `cpu` / `mps` / `cuda` | `auto` |
| `--format` | `srt` 或 `vtt` | `srt` |
| `--sort-by` | 排序依据：`auto`/`ffprobe`/`birthtime`/`mtime`/`name` | `auto` |
| `--recursive` | 目录模式递归查找子目录 | 关 |
| `--polish-level` | `minimal`=只纠错保留全部语气词 / `clean`=额外去水词 | `minimal` |

## 输出文件

三步跑完会在输出目录得到这些文件：

| 文件 | 内容 |
|------|------|
| `<名字>.raw.srt` | **ASR 原文字幕**（纠错前），和正片**逐条对齐**，直接 diff 就知道纠错动了哪些字。双声道时取样点在**跨轨互校之后**——互校会删条目，raw 写在它前面两边条数就对不上，`validate_subtitle` 会把正常的互校删除报成「结构性损伤」。互校删了什么去看 `.spk1/.spk2` 和任务目录。超宽拆条在 raw 和正片上跑的是同一套规则，但纠错让文字变长的那几条可能拆法不同，diff 时表现为新时间码 |
| `<名字>.srt` | **总字幕**（互校 + 纠错后），压进视频用；两人同时说话的条目是两行，每行带 `spk1: ` 前缀 |
| `<名字>.spkN.srt` | 分出了说话人才有：**每个说话人一份**纠错后的字幕，时间轴与总字幕一致，单行无前缀，可单独压片或交给本人核对 |
| `<名字>.spkN.raw.srt` | 分轨**原始**对照：每条轨（声道 / 设备）ASR 原文，含被判为串音的条目（带 `【串音】` 前缀）。查机器丢了什么用 |
| `<名字>.uncertain.srt` | **待确认字幕**：机器认为读不通、但没把握改的地方 + 候选改法，丢进剪辑器逐个跳转听原声核对 |
| `<名字>.dedupe.md` | **连续重复去重对照清单**：每条一行 `[状态] 去重前 → 去重后`，`已回滚` = agent 复核时判定误伤已改回。扫一遍确认规则没削坏意思 |
| `<名字>.manifest.json` | 布局（接续 / 并行）、源文件顺序与排序依据、每个文件在时间轴上的起始偏移；并行时还有对齐可信度、时钟漂移、每个文件的声道 → 说话人映射 |
| `<名字>.highlights.srt` | **关键重点提示字幕（花字）**，叠在画面上用，重点提示 + `【N】` 章节提示合在一个文件 |
| `<名字>.review.srt` | **敏感/冒犯内容审查字幕**，扔进剪辑器逐个跳转决定删改 |
| `<名字>.review.md` | 风险复核清单：时间 / 类别·严重度 / 原文 / 风险点 / 处理建议 |

正片字幕：

```srt
1
00:00:05,605 --> 00:00:08,960
第二个是这里的交互式导入都是我们的特色

2
00:00:10,305 --> 00:00:11,305
第三个是什么？

3
00:00:12,000 --> 00:00:14,800
spk1: 这个我们也是特色
spk2: 对对对
```

第 3 条是两个人同时说话：合成一条两行，**每行前面标说话人**（`spk1: `），
不标的话观众只知道是两个人，不知道哪行是谁。单人条目不标，保持干净。

关键重点提示字幕：章节提示带 `【N】` 前缀，重点提示是裸文字，**两类写在同一个文件里**。

```srt
1
00:01:06,600 --> 00:01:09,200
理解本质比知道能做什么更重要

2
00:01:57,933 --> 00:02:01,433
【1】AI 能帮你磨平技术门槛
```

**不要把章节拆成单独的 `.chapters.srt`**——剪辑器（实测剪映）一个视频只认 3 个字幕文件，
正片 + `.review.srt` + `.highlights.srt` 已经占满，第 4 个拖进去只会提示
「字幕/歌词以默认时间戳展示」。需要单独拿章节时可匹配行首的 `【数字】` 标记。

审查字幕：**时间码和文字都是从正片原样摘出来的**，只在前面加一个类别标签（`--plain` 可去掉）。

```srt
1
00:04:45,200 --> 00:04:52,700
【人身攻击·中】[示例：此处原样摘录待复核的攻击性话语]
```

## 处理规则

### LLM 由谁来做

只通过 **handoff** 交给当前会话的模型处理。脚本将输入和 `TASK.md` 写入任务目录后退出（exit 10）；完成 `out.json` 或就地编辑并写入 `DONE` 后，重跑原命令继续。

任务目录包含输入内容哈希：输入未变时复用结果；字幕或提示词改变时生成新任务。任务文件保留在 `.subtitle_tasks/`，可跨重跑恢复；结果格式不合格会提示修正，字幕结构不合格可回退为分批任务。

ASR 在本地运行；字幕文字、背景和术语表由当前会话模型读取。当前会话使用云端模型时，这些文字会进入该模型的上下文。缓存和任务文件可能保留完整敏感原文，应作为私有素材管理。`--no-llm` 或 `SUBTITLE_LLM=0` 可关闭模型任务，届时语义纠错、风险审查与模型花字不可用。

### 还要不要分批

改成 agent 形式后**输入不再是约束**（agent 自己读文件，没有命令行长度限制；76 分钟、1683 条字幕也才 ~1 万 tokens）。
真正的约束只剩一个：**agent 要写多少字**。所以三个任务的答案不一样：

| 任务 | 输出量 | 分批策略 |
|------|--------|----------|
| 润色 | 和输入 1:1（每条都得原样回传，1683 条 ≈ 3.4 万 tokens） | **必须分批**，每批 100 条 |
| 花字 | 整片几十条 | **整份一次过** |
| 审查 | 命中才几条 | **整份一次过** |

- 润色分批是因为一次写几万 token 会漏返甚至截断，而且我们要能逐批校验、拆半重试；靠 agent 自己"分块写"就没法验证完整性了
- 花字/审查分批**纯属有害**：每批只看得见自己那一段，章节会被批次边界撑爆。
  实测同一份 76 分钟字幕，切 9 批切出 **21 个章节**（3.6 分钟一个），整份一次过是 **7 个**（11 分钟一个），而且更快（一次冷启动 vs 九次）
- 整份 / 切片的门槛按**文字量**判（`fits_single_pass`：正文 ≤6 万字，条数 ≤4000 作兜底），
  超了才退回切片，此时章节预算才降为「每片最多 3 个」。
  **不能按条数判**：开说话人分离后同样长度的视频会被切出更多更短的条目
  （实测 76 分钟 1765 → 2483 条，正文仍是 2.4 万字），按条数卡会误判成「太长」而白白退回切片

**整份丢过去要防 agent 只审了一半**：字幕很长时 agent 可能分块读着读着就收尾了。
所以审查任务的 `out.json` 用带覆盖标记的协议 `{"scanned_to": <实际审到的 cue>, "items": [...]}`，
脚本按 `scanned_to` 往下续审，直到覆盖全片；真中止了会明确报「后面 N 条未覆盖」而不是假装审完。
花字没做这层保护是有意的——花字漏了尾巴，看一眼最后一条章节提示的时间码就知道，
而审查漏了尾巴是**看不出来的**，只会给人「只有 23 处问题」的虚假安全感。

### 多文件布局：接续 vs 并行

| 布局 | 什么素材 | 时间轴 | 说话人 |
|---|---|---|---|
| `sequential`（接续） | 一场录了好几段的视频 | 第 N 段偏移 = 前 N-1 段时长之和 | 各段共用同一套（L/R 声道 = 同两个人） |
| `parallel`（并行） | 对谈时**每人面前一台录音设备**，各自录成一个文件 | 全部对齐到一条共享时间轴，最早开录的 = 0 点 | **每台设备的每条有效轨 = 一个说话人**，全局编号 |

`--layout auto`（默认）：目录里**全是音频文件**就先试并行对齐，对得上才算并行；有视频、或对不上就接续。
视频也可以强制 `--layout parallel`（比如两台相机各录一个人）。

### 并行布局：多台设备同时录

- **对齐靠音频，不靠文件时间**：各设备按键时刻差几秒到几分钟，文件创建时间又常是导出时间，
  所以用每个文件的响度包络（10ms 一帧）做互相关，峰值位置就是时差。
  实测两台手机 80 分钟录音：时差 80.75s，互相关 ncc 0.69、峰值/背景 90 倍（不相关的录音只有 5~8 倍）；
  `ncc < 0.20` 或峰值比 `< 15` 判为对不齐（不相关的录音实测 ncc 0.11、峰值比 4）——auto 下退回接续，强制 parallel 则报错让你用 `--offsets` 手动给
- **漂移**：不同设备的采样钟差几十 ppm，再每隔 10 分钟取 3 分钟窗口各测一次时差，
  拟合斜率；整片累计 ≥50ms 才按 `speed` 校正（实测两台手机 70 分钟只漂 30ms，没到门槛）
- **定轨**：每个文件先走一遍左右声道判定（和单文件一样的三条判据），是两个人就两轨，
  否则整个文件混成一轨。**2 个文件最多 4 个说话人，但以实际分析为准**——
  样例里两个文件都是双单声道（左右相关性 1.00），所以是 2 轨
- **同一声源录了两遍**：两条来自不同文件的轨，归一化包络在有效帧上的相关性 ≥0.90 就判为同一个人
  被两台设备都录了，只保留先开录的那份，manifest 里记一笔
- **N 轨门限分离**（`dual_channel.separate` 的推广，**由分离度决定做不做**）：
  所有轨放到共享时间轴上，先**按设备归一化增益**（取各文件有效帧响度的 p90，
  ≈ 离它最近那个人的近讲电平；同一文件的左右声道不互相归一），
  再逐帧比「本轨 − 最响的别轨」，低 2 dB 以上就硬静音。
  但设备串音比领夹麦大得多（实测手机对手机轨间差中位数只有 2.9 dB），
  这种素材上门限是**净负面**的，所以默认先量分离度再决定，详见下一节
- **设备分不出的人**：一台设备前坐两个人时这两个人在同一轨里（实测样例里 `New Recording 7`
  同时收了两个人、`标准录音 3` 只贴着第三个人）。这种情况设备级分轨只能到「哪台设备」，
  **再往下分不了**——`--speakers` 在分轨模式下会被轨号覆写掉，加了也没用
  （见「已知限制：分轨模式下 `--speakers` 不生效」）。先用 `--probe-speakers` 认出是哪台设备，
  再把那个文件单独拎出来跑一遍声纹，人工对时间轴合并
- **代价**：每轨各转写一遍，ASR 时间 = 轨数 × 单轨；对齐本身只要几秒
- **ASR 缓存 key 带对齐方案的哈希**：多加一个文件就是另一套门限，不会拿旧的分轨结果糊弄
- 对齐结论和轨定义缓存在 `.subtitle_cache/parallel-*.json`，handoff 每轮续跑不用重新解音频

### 多视频合成一个字幕（接续布局）

- **排序**：`auto` 模式下优先读容器元数据里的 `creation_time`（真正的拍摄/导出时间）；只要有任何一个文件缺这个字段，就整体退回文件 `birthtime`——**绝不混用两个时钟**，否则顺序会乱
- **时间轴**：第 N 个视频的字幕整体偏移 = 前 N-1 个视频的 `ffprobe` 时长之和，所以拼出来的时间轴对应的是「把这些视频首尾相接后的成片」，剪辑时必须按同样顺序、不掐头去尾地拼
- 顺序和偏移量都写进 `manifest.json`，事后可核对

### 纠错级别（默认只纠错，不改写）

口播里的「就是」「那个」「对吧」是说话人的真实语气，删掉之后字幕就不像本人说的话了。
所以默认级别是 **minimal：只纠错，不润色**。

| 级别 | 做什么 | 不做什么 |
|------|--------|----------|
| `minimal`（默认，以下专项改写只用于中文） | 同音近音错字、**连续重复的字/词组去重**（「他他需要」→「他需要」、「把这个把这个」→「把这个」）、专有名词、**年份换阿拉伯数字**（「一九年」→「19年」）、中英文空格 | **不删任何语气词和口头语**，不改语序、不换词、不补标点 |
| `clean` | 上面全部 + 去水词（呃嗯啊那个就是）、整条删纯语气词 | 同样不改语序、不换词 |

- 用 `--polish-level clean` 切到去水词模式；需要"顺一遍"给别人看时才用
- **专有名词**：skill 自带 `glossary.txt`（支持 `错写法1, 错写法2 → 正确写法` 映射，自动加载），
  `--glossary` 可追加。术语表没列的也要求 agent **结合上下文推断**，并让同一个词全片保持一致——
  实测 `coso`/`cos` → `Cursor`、`web coding` → `vibe coding` 都能修对
- **拿不准的一律保留原文**，并写进待确认字幕交给人（见下）
- 关闭模型任务时 minimal 级别不做语义纠错，仍保留明确中文的规则去重、年份转换及格式处理；非中文保留原文——规则改不了错别字，乱删水词只会更糟
- **分批策略**：默认每批 100 条 / 4000 字符（谁先到算谁），**并额外附带前后各 12 条只读上下文**。
  批次不能无限大，因为润色要求每条原样回传，瓶颈在**输出**不在输入——一次几百条会让 agent 漏返、甚至截断；
  而只读上下文不用回传，所以能便宜地把前后文补进来，纠错别字和判断句子边界主要靠它
- **漏返保护**：返回条数少于批次的 80% 直接判失败去拆批；少量漏返则保留原文并提示
- **失败自动回退**：答案缺失或无法解析 → 保留原任务并提示补写；结果结构不合格 → 拆批重试，单条仍失败则退规则模式，不丢内容
- **规则模式（关闭模型任务）**：只压缩连续语气词、去重复口癖、删句末语气词；错别字不纠正

### 中文年份转换（中文内容的所有级别）

口播里说的「一九年」「二零二五年」，字幕上写成中文既难认又白占字宽——观众扫一眼要在脑子里换算一次。
所以年份统一换成阿拉伯数字：**「一九年」→「19年」、「一四年」→「14年」、「二零二五年」→「2025年」**。

**只换年份，不换时长**：「十年前」「一年之后」「八年」「半年」说的是跨度不是年份，换成数字反而怪。

和去重一样是**规则 + agent 两道**（`normalize_year_digits`，跑在去重之后、纠错之前，跑完打印换了哪几个）：

| 谁 | 管哪些 |
|---|---|
| 规则 | 最有把握的那批：纯汉字数字（不含十/百/千）、2 位或 4 位（4 位只认 19xx / 20xx）、前面没紧挨着别的数字 |
| agent | 规则不敢动的（「零几年」「两千年」这类），外加把规则换错的改回中文 |

规则刻意放过的两族（换错了比不换更扎眼）：

- **带「十」的一律不动**：「十年」「二十年」「十二年」本来就不是年份写法
- **相邻递增的两位不动**：「三四年」「六七年」「五六年」多半是约数说法（三四年 = 三到四年），
  不是 1934 年——这类交给 agent 结合上下文判
- **四位只认 19xx / 20xx**：口播里的四位年份基本就这两族，别的四位连读多半是卡壳
  （实测「我一五、一九年就觉得」被 ASR 连成「一五一九年」，早期规则换成了 1519 年）

配套：`finalize_text` 的中英文补空格对**数字 + 时间单位**开了例外，
不会把「19年」拆成「19 年」（`年月日号点岁` 前面不补空格）；花字里出现年份同样用阿拉伯数字。

### 中文连续重复字 / 词组去重（中文内容的所有级别）

「因为你你否则你就把…」这种重复不是语气，是 ASR 把一个字吐了两遍（或者说话人卡壳），
留着既难读又白占单行字宽。所以除了让 agent 去重，**还有一道不依赖模型的规则兜底**
（`dedupe_stutter`，minimal / clean、有没有 agent 都跑，跑完打印改了几条）：

| 规则 | 做什么 | 边界 |
|---|---|---|
| 单字 | 只对代词/虚词（`你我他她它您咱了是就都也很这那`）生效，且只压**刚好重复两次**的 | 三连及以上多半是真强调（「对对对」），交给 agent 判 |
| 双字口头语 | 白名单内的才压（就是、然后、那个、这个、对吧、其实、所以、因为、但是、可能、我们、你们、他们、如果） | 白名单外不动，免得误伤「研究研究」「商量商量」「一个一个」 |
| 三字及以上 | 紧挨着的整段重复一律压（「把这个把这个」→「把这个」、「我觉得我觉得」→「我觉得」） | 只处理**紧挨着**的，隔了字就不算 |

单字表刻意**不收**那些「重复两遍正好是另一个词」的字：把（把手）、要（要求）、会（会见）、
还（还钱）、得（得到）、在（在职）、地（地地道道）、着（着急）、**的（「商业目的的解决方案」
里是「目的」+「的」）**——收了就会把「你把把手拆了」改成「你把手拆了」。

整段重复还要放过汉语里两族**合法的重复**（都是实测误伤出来的）：

- 「A 的 A」所属链：「他们的**老大的老大**」≠「他们的老大」→ 单元以「的」开头就不动
- 疑问词任意句式：「你想**怎么读怎么读**」「要**什么给什么**」→ 单元里含 `怎么/什么/多少/哪儿/哪里` 就不动

### 去重会不会误伤？两道复核

规则只看字面、不懂语义，白名单只挡得住**已知**的那几族，所以去重不是「做完就算」：

1. **agent 在纠错的同一轮里复核**（不额外花一轮）：去重排在纠错**前面**，
   整份任务里多给一个只读的 `dedupe.tsv`（`条目序号 <TAB> 去重前 <TAB> 去重后`），
   要求它把削坏意思的条目按第二列改回去。分批模式看不到对照表，
   但纠错提示里写明了典型误伤长什么样，读不通它就会补回来
2. **`<名字>.dedupe.md` 对照清单给人扫**：每条一行 `[状态] 去重前 → 去重后`，
   `已回滚` = agent 判定误伤已改回。1500 条字幕通常也就一两百行，扫一遍很快；
   发现哪条削坏了直接在正片字幕里补字
3. 没有 agent 时（`--no-llm`）第 1 道不存在，跑完会明确警告「没人复核误伤」

- 去重跑在 `.raw.srt` **之后**，所以 raw 保留对应 ASR 引擎原文，diff 一眼看出去重动了哪些字
- 实测那份 76 分钟访谈：1563 条里规则改动 **216** 条。第一版白名单还不含上面两族守卫时，
  逐条人工审 217 条改动查出 **3 条真误伤**（`商业目的的解决方案`、`老大的老大`、
  `你想怎么读怎么读`），补上守卫后这 3 条不再被动，另有 2 条本该去重的反而被救回来了
  （`的那那个`、`的那那种`——旧版被「的」的 lookbehind 挡住了）

### 待确认字幕（人工定夺）

既然规则是"拿不准的一律保留原文"，那些拿不准的地方就不能悄无声息地留在字幕里。
纠错的**同一次 agent 调用**里会顺手写出 `uncertain.json`（不额外花一轮）。

**判据只有一条：人看了会卡住、或者会当成事实记错，才值得报。**

| 报 | 不报 |
|---|---|
| 专有名词/产品名/术语推不出来（`欧英one` → all in one、`tret` → chat） | 说话人自己的口误、说反的语序（「大众创新万众创业」）——他真就那么说的 |
| 成语、固定表达被识别成乱码（`造访天干` → 倒反天罡） | 多字漏字重复但意思清清楚楚（「本身就是物异化了」「产品不能呃要消失」） |
| 人名、公司名、数字（`章山` → 张三（虚构姓名示例）） | 语气词碎片、口头语 |
| 整句语义断裂、半截话，猜不出原意 | 近义词偏差不影响理解（「生产目标」其实是「生产模式」） |
| 一条里混了两个人的话 | 已经在字幕里改掉的（那是噪音） |

判据是**用户实测反馈定的**：一份 24 条的清单里，用户逐条过完，改的全是左列（专名、成语、人名），
右列那几条一律「不变」——理由是「就是一些语气词或者口误，并不影响理解」。
报多了人要一条条排除，比漏报更烦。

每条给出**原文、疑点、2~3 个候选改法、怀疑的依据**，宁可少报也别硬凑。
这些位置在正片字幕里保持对应 ASR 引擎原文，等你听原声确认后手动改。

**时间码不信 agent 抄的**：清单是拖进剪辑器逐个跳转用的，时间错了这份清单就废了。
而 agent 是手抄时间码的——实测 24 条里错了 7 条，**毫秒位几乎都对**（那三位是随机的，抄错自己会发现），
**错的全是分钟位**（+1 / +2），还有两条直接抄成了隔壁那条的时间。
所以 `anchor_uncertain` 拿清单里逐字照抄的**原文**回字幕做匹配，时间码取命中那条 cue 的真实值；
agent 给的时间只降级为排歧线索（同一句话全片出现多次时挑最近的）。匹配不上的会标 `【时间未校准】`。

### 左右声道 = 两个人（自动，双轨分离）

对谈素材（DJI Mic 之类的双发射器）常常是**一人一个领夹麦，各占一条声道**。
这时声道本身就是最可靠的说话人标签，比 cam++ 的声纹聚类准得多，
所以 `--dual-channel auto`（默认）会先判一次，成立就走双轨：

- **怎么判**（三条同时成立才算，见 `dual_channel.analyze`）：
  1. 两声道波形相关性 < 0.5 —— 立体声、双单声道都接近 1，一判就出局
  2. 两侧**都**有足够多「明显比对方响 ≥6 dB」的语音帧（各自的近讲段）
  3. 弱势一方的绝对时长不能太短（≥5 秒且 ≥5% 有效语音），避免把偶发串音当成第二个人
- **压串音（`--gate`，只在分离度够时才做）**：对方的声音会以 -6~-12 dB 漏进本声道。
  按 20ms 帧算响度（100ms 平滑）比较两轨，本轨没对方响的帧**直接置零**
  （前后各留 120ms hold，避免切掉词头词尾）。
  **必须是硬静音，不能只是衰减**：ASR 前端做 CMVN，整体调小 25 dB 对它几乎没影响——
  实测衰减 25 dB 的那一轨照样把对方一整段独白完整转了出来（790 字 vs 静音后的 245 字）
- **但门限只在「各轨确实各收各的人」时才成立**，所以先量一遍**轨间分离度**
  （有效帧上「本轨 − 最响别轨」绝对值的中位数，`dual_channel.separation_db`），
  低于 6 dB 就整个跳过，分离全交给下面的句级清理，详见「什么时候不该做门限分离」
- **两轨各转写一遍**，声道号即说话人号。**代价是 ASR 时间翻倍**
  （实测 20 分钟视频：声道分析 20 秒，L 轨 3.5 分，R 轨 5 分，合计 8.5 分；单轨约 4 分）。
  静音段 VAD 会跳过，但被切碎的那一轨段落多、每段都有固定开销，所以省不下来
- **串音清理**两道，都在 ASR 之后按能量判（文字判不出来——漏过来的串音被硬解出来是一团糊，
  「对对对对对，嗯嗯，好，嗯嗯，分不清楚」这种，跟原话的相似度根本对不上）：
  1. **整句都是对方在说的直接丢**：本轨与对轨的 dB 差在句子里取 p75，小于 0 就丢。
     取 p75 不取均值，是为了留住「对方长篇大论时自己插一句嗯」——
     只要句子里有四分之一以上的时间本轨占优就算数
  2. **两轨重复的去重**：时间重叠 ≥50% **且**文字相似度 ≥0.55，按能量丢掉弱的那一侧
     （只重叠不相似 = 真抢话，绝不能删）
- **跨轨互校**（agent，纠错之前的一轮）：双轨等于同一句话拿到了**两次独立识别**，
  上面两道机械清理只看能量和字面，两轨断句边界一对不齐就会漏
  （实测同一段话 L 轨断成一句 26 秒、R 轨断成一句 10 秒，字面相似度到不了阈值）。
  所以把「两条声道同时有话」的每个区段连同前后各 2 条上下文交给 agent 按语义判：
  同一句被两个麦都收到 → 删糊的那条；两个人真在各说各的 → 一条都不许删；拿不准 → 不动。
  删超过区段内一半条目直接判为跑偏、整轮不采信（删错 = 永久丢失一个人的话）
- **每个说话人一份最终字幕**（`.spk1.srt` / `.spk2.srt`）：从纠错后的总字幕按人筛出来，
  时间轴一致、单行无前缀，可单独压片或交给本人核对。另有分轨**原始**对照
  `.spkN.raw.srt`——回头查机器把哪些判成了串音（被丢掉的条目在这里带 `【串音】` 前缀原样保留，
  判错了人才看得见）
- **抢话**（两人真的同时说）时合成一条**上下两行**的字幕，**每行前面标 `spk1: ` / `spk2: `**——
  不标的话观众只知道是两个人，不知道哪行是谁（三四个人的场合更是）。
  单人条目不标；要每条都标加 `--speaker-labels`。
  合并有两条硬约束：**最多两行**、跨度不超过 `--max-duration`，
  超了就不合并各显各的（不设限时实测滚出过一条 11.9 秒的三行巨块）
- 声道分析结论缓存在 `.subtitle_cache/dual-*.json`，每轨 ASR 结果各有各的缓存

判定不成立（单声道、立体声混录、只有一个人说话）时自动退回原来的单轨流程，不用管。

### 什么时候不该做门限分离（`--gate auto` 在判什么）

门限分离（把别人说话的帧硬静音）只在**每条轨确实各收各的人**时才成立。
所以分完轨之后先量一遍**轨间分离度** —— 有效帧上「本轨 − 最响别轨」绝对值的中位数
（`dual_channel.separation_db`），`auto` 下低于 **6 dB** 就整个跳过门限。

两类素材的实测数字：

| 素材 | 轨间分离度 | 门限 |
|---|---|---|
| 领夹麦 / 各人一支近讲麦（串音 -20 dB 量级） | 13~20+ dB | 开 |
| 两台手机摆在同一张桌上，都收全场 | **2.9 dB**（36% 的帧差不到 2 dB） | 关 |

**为什么低分离度下门限反而更差**（同一段 3.5 分钟素材的四组对照）：

| 配置 | 那一句 | 抢话合成的两行 |
|---|---|---|
| 先混音再单轨转写 | `…服务相关的主播` + `这个现在不是我的主页` | 0（结构上做不到） |
| 分轨 + 门限 hold 300ms | `…服务相关的主播` + `这个现在不是我的主页` | 4 |
| 分轨 + 门限 hold 120ms | `不过这个现在不是我的主页`（词头「只」被削） | 9 |
| **分轨 + 不做门限** | `只不过这个现在不是我的主页` ✅ | **13** |

- 分离度只有 2 dB 量级时，门限在**换人边界**必然削掉词头（`只不过` → `不过`）
- 放宽 `HOLD_MS` 救不了：120 → 300ms 等于把串音放回本轨，混音时那个 `主播` 原样重现
- 门限越狠抢话越少，不是因为分得干净，是因为串音污染让两轨内容变得太像，
  被跨轨去重当成重复删了
- 根子上是**两种错误的代价不对称**：门限是在 ASR **之前**把波形乘 0，判错了音频就没了，
  后面所有环节都救不回来；句级能量判归属是**非破坏性**的，判错了原文还带着 `【串音】`
  标记躺在 `.spkN.raw.srt` 里，人能捞回来

关掉门限后，分说话人全靠 ASR 之后的三道：整句能量判串音 → 时间重叠 + 文字相似去重 →
agent 跨轨互校。担子确实更重（实测弱侧轨 65% 的条目被判为串音），但都是可回溯的判断。

`--gate on` / `--gate off` 可以强制。分离度会打印出来，并在跳过时写进 `manifest.json` 的 `notes`。

### 声纹说话人分离（仅现有中文 FunASR 管线，`--speakers`，双声道素材用不上）

单声道多人对谈里最容易出的错不是错别字，而是**两个人的话被拼进同一条字幕**——
「近来我们陆续探讨一下这个一个夹在哪」这种读不通的句子，本质是 A 的半句 + B 的半句。
这种错光靠纠错模型救不了（它只会硬猜一个通顺的说法），必须在切条目的时候就分开。

左右声道分轨已经从物理上解决了这件事，所以**双声道素材不用开 `--speakers`**；
录成单声道的素材才需要它。开 `--speakers` 后：

- ASR 额外加载 `cam++`，`sentence_info` 带 `spk`，**一个条目只装一个人的话**
- 时间上真重叠（≥200ms）的不同说话人 = **抢话**，`normalize_timeline` 不再削掉这段重叠
  （削掉等于假装两人是轮流说的），渲染前由 `merge_speaker_overlaps` 合成**一条两行字幕**，
  一人一行，自动带「spkN: 」前缀（不然两行分不清谁是谁）
- 没抢话的条目**默认不加前缀**，保持干净可压片；要每条都标就加 `--speaker-labels`
- 合并只发生在**最后的渲染阶段**：润色、存疑清单、审查、花字全都按「一条 = 一个人的一句话」处理，
  粒度不变，也不会让 agent 看见前缀去乱改
- 代价：ASR 缓存的 key 带 `spk=`，所以**开关这个参数会整片重新转写**（76 分钟约 30~40 分钟）

#### 旁人筛选：不是每个"声音不一样的人"都算说话人

cam++ 是**无监督**聚类，它只回答"这些话是不是同一个嗓子"，不回答"这个人是不是这场的说话人"。
路过说两句的、隔壁桌、背景电视，都会各自聚成一"个人"。

真正的麻烦不是名字标错，而是 `merge_speaker_overlaps` 看到两个**不同 speaker** 的条目重叠
200ms 就把它们合成一条上下两行、各带 `spkN: ` 前缀的字幕——背景里一句咳嗽就能让成片凭空多出一个人。

所以认完人先按说话时长排个序（`demote_bystanders`）：

- **给了 `--speaker-count N`** → 严格取前 N 个。注意这时 cam++ 本身已经被 `preset_spk_num`
  约束成 N 簇了，所以这道筛选实际是防守性的
- **没给** → 只降级"又短又少"的簇：说话时长占比 < 3% **且** 绝对时长 < 20 秒，两个条件同时成立才算
- 被判为旁人的**不删**（删错等于永久丢话），原文照留在字幕里，只是**不给说话人标注、不参与抢话合并**
- 每簇的时长和占比写进 `manifest.json` 的 `speaker_clusters`，终端也会打印一行

**为什么只按时长不按响度**：混音单轨没有可靠的分人能量包络（那是双声道/多设备那条路才有的，
见 `dual_channel.mark_bleed_sentences`）。时长排序对"主持人只问三句话"这种真说话人不友好，
所以**人数你清楚的话务必传 `--speaker-count`**，别让它猜。

实测提醒：cam++ 在近讲素材上并不怎么过度聚类（实测往开头拼进 3 秒别人的声音，
它直接并进了已有的簇，没有多聚一个人）。这道筛选是安全网，不是常态会触发的东西。

#### 已知限制：分轨模式下 `--speakers` 不生效

双声道分轨和多设备并行分轨都会在 ASR 之后用**轨号覆写** `spk`
（`generate_subtitle.py` 的 `item["spk"] = track.speaker` / `= speaker`），
cam++ 的聚类结果被整个丢掉。所以**一台设备前坐了两个人时，加 `--speakers` 没用**，
只是白多花一遍加载和转写。

现在的绕法：把那个文件单独拎出来跑一遍 `--speakers`，再人工对时间轴合并。

### 单行字宽：一行最多 16 个中文（硬上限）

竖屏成片在常用字号下，一行超过 16 个中文就会被播放器自己折成第二行，
而**第二行是只留给「两个人同时说话」的**（见抢话合并）。所以单行宽度是硬上限：

- **宽度单位是「一个中文」**：全角/CJK 算 1，英文字母、数字、半角标点算 0.5——
  也就是「2 个英文 = 1 个中文」，`--max-chars 16` 即一行 16 个中文 / 32 个英文字符
- 标点和空格**一起算宽**（它们在屏幕上一样占地方）
- 一个人说话的条目**永远是一行**；两人抢话合成的两行，**每行各自也不超过 16**
  （「spkN: 」前缀不计入这个预算）
- 老版本这里留了 1.6 倍宽限（限 20 却放过 32 字），成片里就是活生生的两行——已经去掉
- **唯一的例外是「切了会劈开术语」**：找不到合法切点时宁可让这一行超宽，
  上限 1.35 倍（`TERM_OVERFLOW`）。两种难看程度不对称——超宽一点点播放器顶多折行，
  而「Refore HTML」换行「to Figma」是语义损伤，观众根本看不出说的是哪个产品。
  详见下面的「不许把词语劈在两条字幕里」

### 断句与时间码

- 时间码全部来自 ASR 的 token 级时间戳，不做任何拉伸平移
- 按标点断句，再在 `--max-chars`（单行字宽）内合并；没有标点的长句只在 token 边界切，
  **不会把英文单词劈成两半**
- **句内停顿 ≥`--pause-split`（默认 0.6 秒）的地方强制断开，两侧绝不并进同一条**。
  这道是给「两个人的话被编进一条字幕」兜底的：FunASR 把所有 VAD 段的文字拼成**一整条**
  交给 ct-punc 打标点，最后 `timestamp_sentence()` **只按标点切句**——VAD 段边界
  （最硬的换人证据）在它那里被丢掉了。所以「A 说完、停 1.4 秒、B 接话」只要 ct-punc
  没在那儿点句号，两个人就并进同一条；`cam++` 的 `distribute_spk()` 又是按最大时间重叠
  给**整句**贴一个说话人号，说话人也跟着错。实测 82 分钟对谈的 2604 句 ASR 句子里，
  8% 内部藏着 >700ms 的停顿。阈值取 0.6 秒是因为 token 间隙 p95 = 220ms、p98 = 500ms，
  正常换气够不着；何况在 0.6 秒的停顿处断条本来就是自然的字幕节奏，判过头也不伤
- 切长句时**先贪心求出最少片数，再按这个片数等宽重切一遍**：26 字宽限 16 会切成 13+13
  而不是 16+10，免得剩下孤零零的尾巴（等宽版本一旦有片超宽就退回贪心）
- **等宽切点会吸附到词边界**（`_snap_to_pause`）：中文每个字都是一个 ASR token，
  纯按宽度切不知道哪儿是词，24 字限 16 切成 12+12 正好落在「…也很需要营 | 销相关的…」
  这种词中间。所以在目标宽度 ±25%（且不超过硬上限）的窗口里挑候选，优先级是
  **词首（jieba 分词）> 前面的停顿更长（token 时间戳：词内间隙≈0，词间几十到几百毫秒）
  > 离等宽目标更近**。实测切在词中间的比例 38.8% → 2.4%（加上停顿硬断后是 0.8%）。
  jieba 是软依赖，拿不到就少一档判据，不报错
- **渲染前还有一道兜底**（`enforce_line_width`）：纠错会让文字变长（`cos` → `Cursor`、
  中英文之间补空格），到这里还超宽的就按 token 边界拆成前后两条，时间按各片字宽比例分。
  这一道只作用在渲染副本上——存疑清单要拿原文回锚，条目粒度不能变。跑完会打印拆了几条
- 输出前统一排序、消重叠、补足最短时长、砍掉超长尾巴，保证条目不重叠且起止不倒置

### 不许把词语劈在两条字幕里（术语保护）

一条字幕以「浏览」结尾、下一条以「器」开头，观众得在脑子里拼一次。最伤的是**产品名被劈开**
——实测「接下来用 Refore HTML」/「to Figma 为例来介绍」，而那恰恰是教程里最该看清的词。

老实现把「词边界」只当成 `_snap_to_pause` 里的一档**软偏好**（窗口里没有词首候选就照切），
现在是**硬约束**：切点不许落在保护区间内部，找不到合法切点就让这一行超宽（≤1.35 倍）。

`protected_spans()` 的保护区间有四个来源：

| 来源 | 挡住什么 | 例子 |
|---|---|---|
| 术语表里的多字/多词术语 | 带空格的**组合产品名**——jieba 和 token 边界都拦不住 | `Refore HTML to Figma`、`Claude Code`、`MCP server` |
| jieba 分词（≥2 字） | 普通中文词 | `浏览器`、`连接器`、`自定义` |
| 数字 + 量词/单位 | 数值和它的单位 | `3 个`、`19年`、`16 字` |
| 数量短语 + 中心名词 | jieba 补不上的那类：它把「一句话」切成「一句」+「话」，按分词没错，可两半分居两条就成了「用一句」换行「话发给…」 | `一句话`、`三个页面`、`一个流程` |

**术语表因此有了两个用途**：纠错时告诉 agent「这个词的正确写法」，断句时告诉切分器
「这几个字是一个整体」。`glossary.txt` 末尾的「组合名 / 复合词」一段是专为后者加的，
只保护不纠错；本工程之外的术语用 `--glossary` 追加，写法一样。

**跨句接缝要先并回来再切**（`repair_term_splits`，跑在 `enforce_line_width` 之前）：
切点校正只管得到一次 `wrap_spans` 内部，而「接下来用 Refore HTML」和「to Figma 为例来介绍」
在 ASR 眼里就是**两句话**，压根没进过同一次切分。所以渲染前先扫一遍相邻条目，
接缝落在保护区间内部的就并成一条，再交给 `enforce_line_width` 按保护区间重切——
切点自然挪到术语外面，输出的是「接下来用 Refore HTML to Figma」/「为例来介绍」，
而不是真的甩出一条超长的。四道闸门任何一道不过就不并：

1. 两条都是单行（抢话合成的两行不动）、同一个说话人
2. 接缝处时间间隔 < 500ms（`JOIN_MAX_GAP_MS`）——超了是真停顿，并了字幕会跟不上口型
3. 并起来不超过 `--max-chars` 的 3 倍（`MAX_JOIN_WIDTH`），免得滚雪球
4. 前一条不是以 `。！？!?…` 收尾的（那是说完了，不是被劈开）。
   **只有术语表命中能推翻这一条**——句号后面接一个新词是再正常不过的断句，
   而句号落在「这个代表你看 Refore。」/「HTML to Figma」中间只可能是标点模型判错了，
   所以 `glossary_spans()`（术语表那一档）说了算，`jieba` 词那一档说了不算。
   注意句末标点在 `finalize_text` 里就被删了，判据取的是删之前记下的 `_sentence_end`

跑完会打印「术语/词语被切在两条字幕里，已并回重切：N 处」。

### 关键重点提示（花字）

- **两种类型**：`chapter`（新章节开始，6~12 字小标题，整片通常 3~8 个）、`highlight`（关键信息提示，8~14 字）
- **只挑「观众会想记笔记」的**：核心概念定义、有洞察的结论金句、关键步骤/命令/路径、容易混淆的对比关系、实用技巧
- **不挑**：复述原话、无信息量的总结、琐碎操作细节
- **准确性**：内容必须能从字幕原文推导，禁止臆造文件名、路径、数字、产品实现细节
- **整份一次过**（正文 ≤6 万字时不分批）：通篇看完再切章节，章节数按全片时长给预算（`min(8, max(3, 时长/8))`）
- 只有超长字幕被迫切片时，才降为「每片最多 3 个章节」，并把前面已划出的章节标题带进后续片段
- 密度由 `--per-minute` 控制，相邻提示强制间隔 `--min-gap` 秒，靠太近时章节提示优先保留
- 每条提示锚定在该信息**开始讲**的那条字幕上，章节提示显示 3.5s、重点提示 2.6s，并自动避让下一条

### 敏感/冒犯内容审查

四个类别，严重度分 高 / 中 / 低：

| 类别 | 覆盖什么 |
|------|----------|
| 敏感信息 | 真实姓名+职务组合、手机号、邮箱、微信/QQ、住址、证件与银行卡号、密码密钥、公司内部数据、客户名单、报价与薪资、尚未公开的计划 |
| 人身攻击 | 针对具体个人的贬低、辱骂、羞辱、能力否定 |
| 引起不适 | 暴力血腥、生理不适、疾病细节、令人尴尬或难堪的描述 |
| 冒犯性 | 脏话、地域/性别/种族/年龄/职业歧视、刻板印象、点名贬低第三方公司或产品 |

- **宁可多报不可漏报**：这是给人复核用的初筛，漏掉的代价远大于误报；因此**没有**花字那样的数量上限
- **原样摘录**：文字逐字复制原文，时间码直接取自正片，不改写、不概括——这样才能在剪辑器里精确定位
- **跨条合并**：一段风险话横跨多条字幕时用 `cue`+`cue_end` 标出整段；重叠或紧邻的命中会合并成一条，同类别只保留最高严重度
- **不报**：正常的技术讨论、产品介绍、对事不对人的评价
- **整份一次过**：通篇看完才判断得准（人名在前面出现、手机号在后面才念这类跨段线索）
- 命中比例超过全片 30% 会给出提醒（多半是模型跑偏了）
- 关闭模型任务时**直接跳过**——这是纯语义判断，规则做不了，硬做只会给出虚假的安全感

## 交付前的检查

1. **结构校验**（三个 srt 都要跑）：

```bash
python3 -c "
import re, sys
text = open(sys.argv[1], encoding='utf-8').read()
blocks = [b for b in re.split(r'\n\s*\n', text.strip()) if b.strip()]
for i, b in enumerate(blocks, 1):
    lines = b.strip().split('\n')
    assert len(lines) >= 3 and lines[0].strip() == str(i) and '-->' in lines[1], f'格式异常: 第{i}块'
ts = re.findall(r'(\d{2}:\d{2}:\d{2},\d{3}) --> (\d{2}:\d{2}:\d{2},\d{3})', text)
assert all(s < e for s, e in ts), '存在起止倒置'
print(f'OK: {len(blocks)} 条，编号连续，无倒置')
" "字幕文件.srt"
```

2. **单行字宽校验**（正片必跑，一行最多 16 个中文；两行只允许出现在抢话条目上，`spkN: ` 前缀不计宽）。
   **超宽不一定是 bug**：为了不劈开术语允许超到 1.35 倍（≤21.6），所以下面把阈值分成两档
   ——超 16 的列出来人眼确认「是不是为了保住一个词」，超 21.6 的才是真异常：

```bash
python3 -c "
import re, sys, unicodedata
w = lambda s: sum(1.0 if unicodedata.east_asian_width(c) in ('F','W') else 0.5 for c in re.sub(r'^spk\d+: ', '', s.strip()))
text = open(sys.argv[1], encoding='utf-8-sig').read()
bad, three = [], []
for b in [b for b in re.split(r'\n\s*\n', text.strip()) if b.strip()]:
    lines = b.strip().split('\n')[2:]
    three += [b] if len(lines) > 2 else []
    bad += [(w(l), l) for l in lines if w(l) > 16]
over = [(x, l) for x, l in bad if x > 16 * 1.35]
print(f'超 16 字宽 {len(bad)} 行（其中超 1.35 倍上限 {len(over)} 行 ← 这些才是异常），三行及以上 {len(three)} 条')
[print(f'  [{x:g}] {l}') for x, l in bad[:10]]
" "字幕文件.srt"
```

3. **扫一遍 `.dedupe.md`**：规则去重的对照清单，确认没把「老大的老大」「目的的」这类合法重复削坏；
   `已回滚` 的是 agent 复核时自己改回去的，不用管
4. **人工过一遍 `.highlights.srt`**：花字是要露出给观众的，臆造成本高，务必确认每条都能在字幕原文里找到依据
5. **先过 `.uncertain.srt`**：这是机器明确说"我读不通但没把握改"的地方，改完再跑审查和花字
6. **人工逐条确认 `.review.md`**：这是机器初筛，**不能**当成「过了就安全」——既会误报也可能漏报，删改与否是人的决定
7. **汇报时说清**：布局（接续 / 并行）、文件顺序与各自偏移（并行时还有对齐可信度、声道 → 说话人映射）、条数变化、修正的专有名词清单、去重几条（回滚几条）、待确认几处、审查命中几处（高危几处）

## 技术说明

- **ASR 模型（中文与多语言两条路径，`--engine`）**：
  - `funasr`（中文声纹路径）：`paraformer-zh` + `fsmn-vad` + `ct-punc`；`--speakers` 时额外加载 `cam++`
  - `firered`：FireRedASR2S = `FireRedVAD` + `FireRedASR2-AED` + `FireRedPunc`（仅承担中文转写；语言检测由 Whisper 完成）。**没有声纹分离**，`--engine firered --speakers` 会直接报错，
    多说话人只能靠 `--dual-channel` / `--layout parallel` 按声道或设备分轨
  - `whisper`：非中文、多语言转写，始终 `task="transcribe"`；词时间戳按文本映射到 Unicode 字素，实际语言支持随 checkpoint 检查。
  - 为什么不是初代 FireRedASR：初代只吐一整串文字，**没有词级时间戳、没有 VAD、没有标点**，
    单次输入还卡 60 秒上限。本脚本的拆条、重算起止、串音判定全都建立在词级时间戳上，初代接不上
- **喂给 ASR 的是抽出来的 16k 单声道 wav**（`ffmpeg -vn`），不转码视频本身，所以没有体积上限、也比转码快得多；
  双人双轨时改成解 16k 双声道、压掉串音后写出两条单声道 wav（`dual_channel.py`）
- **三种返回结构都兼容**：FunASR 带 `cam++` 时用 `sentence_info`；不带时用整段 `text` + token 级 `timestamp`，按句末标点切回句子后再分派时间戳；FireRedASR2S 直接给断好句的 `sentences` + 全局平铺的词级 `words`，按时间顺次分派给各句（`firered_asr.to_sentences`）
- **ASR 结果缓存**在输出目录的 `.subtitle_cache/`（按文件路径+大小+纳秒修改时间+**实际引擎/音频提示/检测语言/模型身份**做 key，双轨时每条声道各一份；换引擎不会串用旧结果），改参数重跑、或只重跑润色时不必重新转写；
  同目录的 `dual-*.json` 缓存的是声道分析结论 + 每 100ms 的左右声道响度包络（串音清理要用它）
- **多设备对齐**：`multi_track.py`，10ms 响度包络 FFT 互相关 + 分窗口漂移拟合 + N 轨门限
  （门限是否执行由分离度决定，见 `decide_gate`）；
  每轨单独解码、门限、写 wav、转写，用完即放，内存不随轨数累积
- **ASR 缓存 key 带门限开关**（`nogate` / `m-2.0h120`）：开不开门限就是两份不同的音频，
  不会拿旧结果糊弄
- **支持格式**：视频 mp4/mov/mkv/avi/wmv/webm/m4v/3gp/mpeg/mpg/flv/ts，音频 m4a/mp3/wav/ogg/flac/aac/wma/opus
- **耗时**：ASR 耗时取决于设备和引擎，模型任务耗时取决于当前会话的模型与字幕规模。handoff 等待不会触发脚本中的模型调用超时。
- **退出码**：`0` 正常；`1` 出错；`2` 翻译因存疑暂停；`10` handoff 有任务等你做（不是失败，照着清单做完重跑即可）

## 与其他 skill 的关系

这些配套 skill 按需使用。`podcast-episode` 提供可选的 `transcript_lib`：可用时额外生成 `transcript.json` 与持久化混音；缺失时跳过这两项，字幕主体功能仍可使用。

- `subtitle-translate-en`：已有中文到英文专用 Skill；本 Skill 的多语言翻译使用自身 `translate_subtitle.py` handoff，不隐式调用会再次润色原字幕的流程
- `analyze-video-materials`：需要抽帧、证据帧、逐帧视听分析时用那个；本 skill 只管字幕
